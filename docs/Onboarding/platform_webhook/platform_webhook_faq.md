# Understanding events

Webhook events are JSON payloads which are posted by the Purchasely Platform, directly to the webhook endpoint URL configured in the Console.

These events are part of the [Purchasely Analytics](https://purchasely.readme.io/docs/purchasely-analytics) composed of

1. **[Transactional Events](https://purchasely.readme.io/docs/transactional-events)** - used to manage entitlements and get revenue information about transactions
2. **[Subscription Events](https://purchasely.readme.io/docs/analytics_subscription_events)** - used to get a more comprehensive overview of the subscription lifecycle
3. **[UI / SDK Events](https://purchasely.readme.io/docs/ui-sdk-events)** - generated inside the app and useful to understand how users interact with Purchasely screens

In this section, we will only focus Transactional Events for the sake of managing the entitlements.

The Events always have the [same structure and are composed of set of attributes](https://purchasely.readme.io/docs/transactional-subscription-events-attributes).

# Receiving and acknowledging webhook events

Transactional Events sent on the webhook by the Purchasely platform need to be acknowledged by the developer backend to confirm to the Purchasely Platform that they have been processed.

This acknowledgement is done by responding to the message with a `HTTP 200` response code.

After the Purchasely Platform has received the response, it notifies the Purchasely SDK to confirm to the user that they are now a premium member and can have access to the premium contents / features. 

The Purchasely Platform implements a **retry mechanism** when a message is not acknowledged to prevent the risk to lose any message.

When a message is not acknowledge, the Purchasely SDK gets notified that something went wrong while granting the entitlements and the user is invited to retry in a few minutes.

# Determining which user is concerned by an Event

The Purchasely SDK can manage 2 types of users:

* <Glossary>connected user</Glossary>
* <Glossary>anonymous user</Glossary>

The Transaction will reflect the status of the user inside the app when the transaction occurred:

* If the user was anonymous, the payload will carry the attribute` anonymous_user_id`, which value is generated randomly by the Purchasely SDK upon its first initialization and can be fetched by the app from the SDK using the `getAnonymousUserId` API.
* If the user was connected, the payload will carry instead the attribute `user_id`, which value is provided by the app to the Purchasely SDK either when the it starts (if the user is already signed-in) or when the user signs-in, by using the `userLogin` API of the Purchasely SDK.

Note: when a user makes a purchase as an <Glossary>anonymous user</Glossary> and then sign-in afterwards, the transactions and associated subscriptions will automatically be transferred from the <Glossary>anonymous user</Glossary> to the <Glossary>connected user</Glossary>. The appropriate webhook events to reflect this transfer will be automatically generated by the Purchasely Platform.
